# 重构落地检查清单

清单分四段：发提示词前 → 应用 AI 输出前 → 应用后 → 合并前。每条都尽量能用命令或代码核对，而不是靠「感觉没问题」。提示词生成与自检工具见 [README](../README.md) 与 [SKILL.md](../SKILL.md)。

## A. 发提示词前（30 秒自检）

- [ ] 八段齐全：角色、上下文、待重构代码、硬约束、重构目标、验收标准、输出格式、守卫
- [ ] 验收标准里有**可运行命令**（`go test` / `pytest` / `cargo test` / `npm test` / `dotnet test` / `mvn test` …），且与语言匹配
- [ ] 硬约束写明「行为 / API / 返回值 / 异常」不变
- [ ] 【重构目标】第 0 条是「先生成/补齐行为基线测试」
- [ ] 输出格式已选：unified diff 必须声明基线文件
- [ ] 没有「顺便改测试」「整个项目重写」「最佳实践重写」「性能更好」等反模式

命令：

```bash
python3 scripts/check_prompt.py prompt.txt --strict   # 警告也算问题
python3 scripts/check_prompt.py prompt.txt --fix      # 缺失段落直接补骨架
```

## B. 应用 AI 输出前（评审 diff）

- [ ] diff 声明的基线与当前 HEAD 一致；单批改动可评审（建议 < 400 行）
- [ ] 没有新增第三方依赖；没有弱化错误处理、日志、安全校验
- [ ] 测试文件只增不改：既有断言原样保留
- [ ] 公开签名、返回值、异常类型未变
- [ ] 改动清单表格完整：每处改动 → 改了什么 → 为什么 → 影响面

## C. 应用后（跑验收）

- [ ] 行为基线测试全绿（新增的 + 原有的）
- [ ] 差分测试 / golden 对照全绿（如适用）
- [ ] 无法跑测试时，等价验证步骤逐条执行并记录输出
- [ ] 失败时回喂最小信息（失败用例 + 相关片段）；连续两轮失败回滚该批

## D. 合并前（工程门禁）

- [ ] 每批独立可回滚：commit 粒度 = 批次粒度
- [ ] 变更说明写清「行为不变」的依据（命令 + 结果），而不是一句「已重构」
- [ ] CI 绿灯（若有）
- [ ] 确实要改行为的需求另开变更单，不混进重构提交
